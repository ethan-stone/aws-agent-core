# ADR 0002: Incident-Linked Agent Conversations

Incident collaboration happens on the shared incident surface, while agent work happens in linked Conversations. Incident comments and mentions are created by the webbackend/service layer; accepted `@copilot` mentions and automation triggers create incident-linked Conversations and visible IncidentActivity cards. Runtime lifecycle scaffolding updates those cards when the running agent blocks on approval or authorization, completes, fails, or is cancelled, because those states are caused by the AgentRun lifecycle. Mention-created ops-copilot Conversations remain ordinary interactive agent conversations owned by the mention author, while automation-created incident-responder Conversations are observe-only except for eligible RequiredAction resolution. IncidentActionApproval is the incident-surface projection of tool approvals only for observe-only incident automation Conversations; mention-created copilot Conversations and their child runs use the normal conversation RequiredAction flow. Specialist agents such as incident-responder are invoked by automation or agent orchestration rather than direct user mention.

Sub-agent delegation from ops-copilot to incident-responder is intentionally deferred. The domain model keeps room for delegated child AgentRuns, but the first incident collaboration slice does not depend on Strands multi-agent behavior or decide how child-agent approval interrupts surface to users.

The first slice includes ops-copilot and incident-responder as the real AgentKinds, IncidentActivity instead of IncidentEvent, IncidentComment, one actionable `@copilot` IncidentAgentMention per comment, incident-linked Conversation metadata, observe-only incident-created automation, and IncidentActionApproval projection for observe-only automation tool approvals. It excludes direct `@incident-responder` mentions, sub-agent delegation, multiple actionable mentions in one comment, generic user-started incident-responder conversations, and full tool-trace projection into the incident feed.

Incident linkage, interaction mode, and interaction owner belong on Conversation: use `Conversation.incidentId`, `Conversation.interactionMode`, and optional `Conversation.interactionOwnerUserId`. AgentRun may still carry incidentId for runtime projection compatibility, but Conversation is the source of truth for whether the thread is incident-linked and who may add ordinary follow-up messages.
